⛔ Blocking finding: the route layer does not exist

gtplanner_backend_simple/api/ is an empty directory — no auth.py, prd.py, documents.py, llm_config.py, workflow.py, not even __init__.py. A full-repo search finds zero APIRouter definitions, yet main.py mounts five. Result: ModuleNotFoundError at import — the backend cannot boot anywhere, and the 9 test files importing main.app die at collection. The API contract survives only inside web_simple/src/services/api.js (~25 endpoints) and test assertions.

C1 · Restore the route layer as the explicit contract seam

Strong

Files: gtplanner_backend_simple/api/* (missing), main.py, web_simple/src/services/api.js

Problem: The interface between frontend and backend has no module — the seam lives implicitly inside api.js and test assertions. Contract drift is undetectable, and nothing boots. Routes should be deliberately shallow adapters: parse → call service → map errors.

Solution: Recreate the five router modules + api/deps.py (auth/admin dependency), generated against api.js. Add one contract test asserting every api.js path exists in the OpenAPI schema.

Benefits: Locality — the contract lives in one place. High leverage — unblocks boot and 8 broken test files. Tests go from collection-error to meaningful.

Deletion test: complexity is missing, not misplaced — this is reconstruction before deepening.

C2 · Kill import-time singletons; inject a settings/provider seam

Strong

Files: core/config.py (module-level settings = get_settings()), services/auth_service.py, core/encryption.py, services/openai_service.py — all construct singletons at import

Problem: Importing any service executes config validation and builds clients. Tests must pre-set OPENAI_API_KEY just to import, then patch singleton attributes with no restore (test_auth_api.py) — classic no-seam, cross-file test pollution. No locality: wiring is smeared across import time.

Solution: get_settings() with lru_cache; services take settings/db/client via __init__; FastAPI Depends providers in api/deps.py become the single wiring point.

Benefits: Fresh instances per test instead of monkey-patch-and-pray; config errors surface at call time with actionable messages; wiring has one address.

Deletion test: deleting the four singleton instantiations concentrates wiring into one provider module — passes.

C3 · One deep PRD generator behind one seam

Strong

Files: services/openai_service.py (183 L), services/workflow_service.py (L411–480)

Problem: Two parallel generation paths, each embedding its own copy of the PRD JSON-schema prompt — pure contract-drift risk. openai_service is async def wrapping the sync OpenAI client (blocks the event loop) and does except Exception → raise Exception. Meanwhile workflow_service already has the right seam (call_llm_json) — the good pattern is trapped inside the wrong module.

Solution: One PRDGenerator module: prompt templates as data, call_llm_json (or an injected LLM client interface) as the only I/O seam, parse_llm_json inside. Both the simple route and the generation workflow consume it.

Benefits: One place to fix prompting (the product's core!); tests mock the client interface instead of patching methods; async fixes apply once.

Deletion test: deleting openai_service concentrates generation logic — passes.

C4 · Split the workflow god module along its existing seams

Worth exploring

Files: services/workflow_service.py (765 L, 25 methods)

Problem: State CRUD + prompt building + mermaid validation + markdown assembly + diagram orchestration in one class. Shallow at the class level: interface ≈ implementation complexity. No locality — understanding "finalize" requires the whole file.

Solution: Keep a slim orchestrator; extract the workflow state repository, a prompts module (shared with C3), and a diagrams module (validate / request / regenerate). The existing constants SECTIONS / DIAGRAMS and call_llm_json are the natural cut lines.

Benefits: Each part unit-testable without LLM mocks; AI-navigability — module names map to PRD concepts (generation workflow, section drafts, diagram).

Deletion test: deleting the whole module just moves 765 lines — must be split, not deleted.

C5 · One schema source of truth

Worth exploring

Files: models/*.py, core/database.py (init_db DDL), database/init/init-simple.sql, models/session.py

Problem: Schema is defined twice (SQLAlchemy models vs SQL bootstrap) with real drift — the SQL users table has no role column and lacks the workflow/llm tables; _ensure_user_role_column is a hand-rolled migration patching one symptom. The chat Session model is imported by init_db but consumed by nothing — dead schema. Document CRUD is a shallow module: query + commit + validate ×5 with the ownership filter copy-pasted.

Solution: Models (+ Alembic later) as the single source; delete the SQL bootstrap and the patch-up migration; delete the dead session model; fold document ownership into a repository default scope.

Benefits: Onboarding no longer requires reconciling two schemas; migration history becomes reviewable; document queries get one address.

Deletion test: deleting SQL bootstrap + dead model concentrates schema truth — passes.

C6 · One conftest to un-rot the test suite

Strong

Files: tests/*.py — 5 copies of engine + override_get_db + fixtures; only 2 of 16 files are importable today

Problem: No shared bootstrap, so every file reinvents the seam — which is how two different JWT libraries (jwt vs jose) slipped in, and why 7 files still import the deleted legacy gtplanner.agent.*. The suite cannot act as a safety net.

Solution: tests/conftest.py providing the TestClient, SQLite DB, and jose-based auth headers; quarantine or delete the 7 legacy test files.

Benefits: This is the leverage point for every other candidate — each refactor step gets a cheap safety net. Cross-file pollution (singleton patching) disappears once C2 lands.

Deletion test: deleting per-file boilerplate concentrates setup — passes.

🎯 Top recommendation

Start with C1 (restore the route layer), immediately followed by C6 (shared conftest). Nothing else can even be verified until the app boots: today the backend fails at import (ModuleNotFoundError on .api), 14 of 16 test files are unimportable, and every fix attempt is a guess. C1 is reconstruction against a contract that already exists (web_simple/src/services/api.js + test expectations), so it is low-risk and unblocks everything. C6 turns the unlocked tests into the safety net for C2 → C3 → C5 → C4, in that order: seams for wiring first, then one deep PRD generator (the product's core), then schema truth, then the god-module split.
